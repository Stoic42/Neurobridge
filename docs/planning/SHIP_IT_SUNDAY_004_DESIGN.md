# NeuroBridge Live Bridge - 架构与 UI 设计图

**版本**: v2.0 (Live Bridge)  
**设计文档**: 技术架构图和 UI 线框图

---

## 🎯 使用场景说明

Live Bridge 支持**两种使用模式**，适应不同沟通需求：

### 模式 1: 面对面协作（Co-located）⭐ 推荐用于 Demo

**场景描述**:
- 两个人在**同一空间**（如：同一房间、同一桌子）
- 可以**共享一个屏幕**（如平板、大屏），或**各自使用自己的设备**
- 实时看到对方的输入和 AI 分析结果

**适用场景**:
- 情侣面对面沟通
- 家长-孩子对话
- 同事协作讨论
- 治疗师-来访者会话

**优势**:
- 可以同时看到对方的非语言线索（表情、手势）
- 结合面对面交流的丰富性和 AI 中介的清晰性
- 适合 Demo 展示（现场可以找人做 live demo）

**界面设计**:
- 如果共享屏幕：左右分屏，中间 AI 层
- 如果各自设备：每个设备显示自己的面板 + 对方的输入 + AI 分析

### 模式 2: 远程沟通（Remote）⭐ 推荐用于实际使用

**场景描述**:
- 两个人在**不同地点**（如：不同房间、不同城市）
- 各自使用自己的设备
- 通过 WebSocket 实时同步对话

**适用场景**:
- 远程工作协作
- 异地情侣沟通
- 远程治疗/咨询
- 疫情期间无法见面时

**优势**:
- 突破地理限制
- 适合 ASD 用户（可能对面对面交流有压力）
- 文献支持：远程机器人中介系统在 ASD 训练中有效

**界面设计**:
- 每个用户看到：
  - 自己的输入面板（左侧）
  - 对方的输入和消息（右侧）
  - AI 分析结果（中间）
  - 对话历史（底部时间线）

### 技术实现

两种模式使用**相同的技术架构**（WebSocket）：
- **面对面模式**: 连接到同一服务器房间，可以共享房间 ID
- **远程模式**: 通过房间 ID 配对，远程连接

**关键区别**:
- 面对面：可以结合非语言线索（需要在界面设计时考虑）
- 远程：完全依赖文本 + AI 分析（更符合当前设计）

---

## 💡 设计建议

### 当前设计重点：远程模式

基于文献研究和技术可行性，**当前设计优先支持远程模式**：

1. **技术优势**: WebSocket 天然支持远程实时通信
2. **用户需求**: ASD 用户可能对面对面交流有压力，远程模式更友好
3. **文献支持**: 远程机器人中介系统在 ASD 训练中显示有效性
4. **扩展性**: 远程模式可以轻松扩展到面对面模式

### 未来扩展：面对面模式增强

可以在未来版本中添加：
- **摄像头集成**: 非语言线索识别（表情、手势）
- **共享屏幕模式**: 优化面对面共享屏幕的体验
- **本地网络优化**: 面对面时使用本地网络减少延迟

## 🔄 交互流程

### 场景 1: 用户发送消息

```
User A 输入文本
    ↓
点击 [Send] 按钮
    ↓
显示 "Sending..." 状态
    ↓
WebSocket 发送消息
    ↓
消息出现在 LeftPanel
    ↓
(异步) AI 分析开始
    ↓
AICenter 显示 "Analyzing..."
    ↓
分析结果返回
    ↓
AICenter 更新显示:
    - Intent
    - Misread
    - Rewrite Suggestions
    - Emotion Intensity
    ↓
RightPanel 显示收到的消息
```

## 🎯 核心设计原则（基于实证研究）

### 原则 1: 双向对称支持 ⭐⭐⭐⭐⭐

**理论基础**: 双向系统用户满意度 70-85% vs 单向系统 50-65%

**设计实施**:
- 确保 ASD 和 NT 用户都能获得 AI 中介支持
- 双向实时反馈，而非单向辅助
- 对称的界面布局和功能访问

**预期效果**: 
- 用户满意度达到 70-85%
- 神经多样性用户互惠性改善 +40%

### 原则 2: 上下文自适应 ⭐⭐⭐⭐⭐

**理论基础**: 双向系统接受度提升 15-25%（基于 EVT 和 TAM）

**设计实施**:
- 根据对话目标（清晰度、共情建立）调整干预
- 动态调整反馈粒度（句子级 vs 消息级）
- 个性化适应用户模式和偏好

**预期效果**:
- 用户接受度提升 15-25%
- 减少"Empathy Fog"（共情模糊）

### 原则 3: 多模态反馈 ⭐⭐⭐⭐

**理论基础**: 多模态反馈提升参与度和理解力

**设计实施**:
- **视觉反馈**: 情绪强度计、改写建议覆盖层、误解提醒
- **听觉反馈**: 微妙的音频提示、语音合成改写建议
- **触觉反馈**: 振动模式（可自定义强度）

**同步原则**: 
- 跨通道同时反馈（视觉图标 + 触觉脉冲 + 音频提示）
- 延迟 < 100ms（使用 WebSocket 协议）

**预期效果**:
- 提升参与度（会话时间、互动频率）
- 改善理解力（误解率降低）

### 原则 4: 透明性和用户控制 ⭐⭐⭐⭐

**理论基础**: 透明度建立信任，减少对他人 AI 使用的错误认知

**设计实施**:
- 明确显示 AI 的角色和功能
- 用户可控制反馈强度和建议粒度
- 允许用户选择接受/拒绝 AI 建议

**预期效果**:
- 建立用户信任
- 减少对 AI 中介的担忧

### 原则 5: 包容性和风格多样性 ⭐⭐⭐⭐

**理论基础**: 支持多样沟通风格，减少对神经多样性用户的疏离

**设计实施**:
- 避免强制"NT 化"表达
- 支持多种沟通风格（正式/非正式、简洁/详细）
- 提供共情语调选项（"I feel..." vs "You are..."）

**预期效果**:
- 提升用户自主感
- 减少对沟通风格的偏见

## 🔄 多模态反馈设计（基于实证研究）

### 视觉反馈机制

**实施**:
- **情绪强度计**: 动态显示实时情绪分析，帮助 NT 用户理解 ASD 伙伴情绪状态
- **改写建议覆盖层**: 在共享对话空间中提供改写选项提示
- **误解提醒**: 基于意图分析算法的闪烁边框或图标

**设计原则**:
- 非侵入性：不打断对话流程
- 视觉友好：符合 ASD 感官敏感需求
- 可自定义：允许用户调整视觉强度

### 听觉反馈机制

**实施**:
- **微妙音频提示**: 成功意图传输的轻柔提示音、检测到误解的警告音
- **语音合成集成**: AI 生成的改写建议通过合成语音传递
- **环境音效**: 适应对话流的背景音频，增强共享空间感

**设计原则**:
- 可关闭：允许用户关闭音频反馈
- 强度可调：适应感官敏感度
- 非侵入性：不干扰对话

### 触觉反馈机制

**实施**:
- **振动模式**: 短脉冲（词级建议）、长脉冲（句子改写）
- **个性化强度**: 基于用户配置的可调振动强度
- **感官友好**: 避免过度刺激

**设计原则**:
- 感官友好：符合 ASD 感官处理需求
- 可自定义：强度可调
- 可选：用户可选择启用/禁用

### 同步策略

**核心原则**:
- **时间同步**: 跨通道同时反馈（视觉 + 触觉 + 听觉）
- **自定义**: 允许用户切换模态，减少认知负荷
- **AI 中介角色**: 基于意图分析优先反馈，整合改写系统
